# Конвертация цифровых («живых») PDF-чертежей без OCR

Этот эксперимент находится в ветке `feature/native-drawing-conversion`, которая создана от `refactor/one-click-smart-ocr`. Обычные OCR-режимы сохранены. Цель — извлекать настоящие PDF-текст и структуру таблиц, а не заново угадывать символы по картинке.

## Поддерживаемый источник

- Цифровой PDF, в котором можно выделить/скопировать текст (PDF text objects, а не растр или кривые шрифта).
- Векторные линии, схемы, контуры, штриховка, встроенные картинки остаются на высококачественном фоне.
- Одна выбранная страница PDF → один слайд PPTX. В GUI можно выбрать номер страницы, в CLI есть `--pdf-page`.
- PDF с `Rotate=90/180/270`, зашифрованные файлы, PDF целиком из изображения и PDF без живого текста пока не конвертируются; программа сообщает причину вместо имитации хорошего результата.

## Принцип работы

1. PyMuPDF читает реальные текстовые операторы PDF (`get_text('dict')`) вместе с координатами строк, размером шрифта, цветом и порядком блоков. **OCR, Paddle и OpenRouter не запускаются**.
2. Несколько строк из одного PDF text block собираются в один редактируемый PowerPoint-фрейм. Это уменьшает разрывы CAT-сегментов. Межколоночные/многоблочные объединения автоматически не выдумываются.
3. `Page.find_tables(strategy='lines')` ищет настоящие линованные таблицы. Реальные прямоугольники ячеек дают колонки, строки, объединения `rowspan`/`colspan`. Структура проходит строгую проверку непересекающихся ячеек. При неоднозначной сетке текст остаётся обычными фреймами, чтобы не терять его.
4. Отдельная **копия PDF только в оперативной памяти** рендерится с удалёнными текстовыми глифами (`apply_redactions(images=0,graphics=0,text=0, fill=False)`). Линии схемы и таблиц остаются. Фон исходного PDF НЕ перезаписывается.
5. Оригинальный текст возвращается в PPTX уже как **редактируемые объекты**, а таблицы — как нативные PowerPoint-таблицы. Для этого режима текстовые рамки прозрачные, белые маски не нужны.
6. Проект `.socr.json` сохраняет исходный PDF с контрольной суммой, номером страницы, отрендеренным фоном и полным списком объектов. При повторном открытии фон сверяется с исходными байтами PDF.

**Важное ограничение:** геометрия схем и линии таблиц пока находятся в высококачественном растровом фоне, поэтому их нельзя редактировать как отдельные PowerPoint-линии. Редактируются текст и ячейки таблиц. Следующий возможный этап — отдельный конвертер PDF path → native PowerPoint shapes и многослайдовые документы.

## Windows / PowerShell

Обновить и установить PDF-зависимость в существующем окружении:

```powershell
git switch feature/native-drawing-conversion
git pull
.\.venv-vl\Scripts\python.exe -m pip install "PyMuPDF>=1.26.4,<2"
.\run-vl.ps1
```

Выберите PDF в главном окне; режим **«Цифровой PDF · структура без OCR»** включится автоматически. Если файл многостраничный, укажите номер страницы. Нажмите «Извлечь PDF → PPTX». Не нужны API-ключ и GPU.

CLI:

```powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\digital.pdf" --ocr-engine native_pdf --pdf-page 1
```

Для PDF на несколько страниц можно последовательно повторить команду с `--pdf-page 2` и т. д. Используйте `--output` для явных имён PPTX; по умолчанию сохранённые файлы не перезаписываются.

## Критерии качества

- Глифы исходного текста не остаются под редактируемыми фреймами (нет двоения); линии схемы не исчезают под белой заливкой.
- Многострочные поля остаются единой текстовой областью, пригодной для CAT; повторяющиеся номера и контакты не теряются.
- Короткие обозначения и цифровые коды сохраняются как редактируемые фреймы, потому что удалены из фона PDF.
- Структура таблиц совпадает с исходными линиями, объединённые ячейки в PPTX правильно расположены.
- Ошибки кодировки PDF, пропущенные при векторизации буквы и сложные таблицы явно помечаются для проверки.

Начальный тестовый набор генерирует векторный PDF с пересекающей подпись линией, многострочным блоком и таблицей с объединённой шапкой. Для настоящей работы особенно важно проверить PDF из CAD, InDesign и Office: некоторые из них визуально цифровые, но содержат символы как контуры — их распознать этим способом нельзя.
