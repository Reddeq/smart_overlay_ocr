# Конвертация цифровых («живых») PDF-чертежей без OCR

Этот эксперимент находится в ветке `feature/native-drawing-conversion`, которая создана от `refactor/one-click-smart-ocr`. Обычные OCR-режимы сохранены. Цель — извлекать настоящие PDF-текст и структуру таблиц, а не заново угадывать символы по картинке.

## Поддерживаемый источник

- Цифровой PDF, в котором можно выделить/скопировать текст (PDF text objects, а не растр или кривые шрифта).
- Векторные линии, схемы, контуры, штриховка, встроенные картинки остаются на высококачественном фоне.
- Одна выбранная страница PDF → один слайд PPTX. В GUI можно выбрать номер страницы, в CLI есть `--pdf-page`.
- PDF с `Rotate=90/180/270`, зашифрованные файлы, PDF целиком из изображения и PDF без живого текста пока не конвертируются; программа сообщает причину вместо имитации хорошего результата.

## Принцип работы

1. PyMuPDF читает реальные текстовые операторы PDF (`get_text('dict')`) вместе с координатами строк, размером шрифта, цветом и порядком блоков. **OCR, Paddle и OpenRouter не запускаются**.
2. Несколько строк из одного PDF text block собираются в один редактируемый PowerPoint-фрейм. Это уменьшает разрывы CAT-сегментов. Межколоночные/многоблочные объединения автоматически не выдумываются.
3. Сначала собственный **CAD vector-grid** ищет многократно повторённые горизонтальные векторные линии и определяет точные вертикальные границы. Отсутствующая граница между двумя элементарными клетками означает объединение; проверяется, что все объединения прямоугольные. Только когда такая структура не обнаружена, используется `Page.find_tables(strategy='lines')` для небольших простых таблиц. При этом внешняя рамка чертежа отбрасывается как ложная «таблица». Для каждой ячейки извлекаются **отдельные символы исходного PDF** с их координатами, поэтому строки, пересекающие границы двух колонок, разделяются без OCR. Потенциальная потеря значительной части текста блокирует предложение таблицы.
4. **Весь исходный лист рендерится без изменений**, включая оригинальные ГОСТовские символы, линии, таблицы и изображения. Текст из PDF больше НЕ удаляется из подложки. Файл PDF не перезаписывается.
5. Текст и таблицы возвращаются как **редактируемые объекты** поверх неизменённого листа. Есть два режима: **«Видимые надписи · как OCR»** — небольшие белые маски только поверх исходных глифов и видимые редактируемые надписи, прозрачные ячейки не закрывают линии таблиц; **«Точный оригинал»** — белых масок нет и исходный PDF виден пиксель-в-пиксель, но редактируемый текст сделан **полностью невидимым** (его нужно сделать видимым для последующего оформления перевода).
6. Проект `.socr.json` сохраняет исходный PDF с контрольной суммой, номером страницы, нетронутым фоном, полной структурой и выбранным режимом наложения. При повторном открытии подложка сверяется с оригинальными байтами PDF. Ранее сохранённые проекты с очищенной подложкой остаются читаемыми.

### Что выявил реальный чертёж «Арматурный блок НГС 2400-40»

Проверка исходного PDF и первой версии PPTX выявила две независимые причины плохого совпадения:

- Почти весь чертёж набран **GOSTTypeA**, а первый алгоритм принудительно заменял его на **Arial**. Теперь сохраняется исходное имя шрифта и размер **каждого блока/ячейки**, но это **не встраивает сам шрифт в PowerPoint**. Оригинальный PDF содержит встраиваемый PDF-поднабор GOSTTypeA, который не переносится в PowerPoint как полноценная офисная гарнитура. Для видимых редактируемых наложений требуется установленный и лицензированный `GOSTTypeA`; иначе PowerPoint подменит его. При режиме **«Точный оригинал»** внешний вид исходных надписей сохраняет сама неизменённая подложка. Шрифтовые файлы не извлекаются, не устанавливаются и не распространяются.
- `find_tables` видел 3 кандидата (включая огромную рамку листа), но исходный конвертер построил только 1 настоящую PPTX-таблицу. В векторных линиях чертежа таблица штуцеров имеет **8 вертикальных границ и 11 горизонтальных уровней**, а спецификация содержит регулярные строки с более чем 20 уровнями. Новый CAD-парсер строит сетку из **этих исходных линий** вместо некорректного общего детектора.

**Это пока исходники и тесты, а не гарантия внешнего вида на любой Windows-системе.** Если PDF содержит неверную таблицу Unicode для собственных шрифтов, текст иногда извлекается неправильными символами; конвертер помечает подозрительные строки, но не подменяет символы догадками. В подобных случаях для отдельных надписей потребуется адресное исправление/распознавание.

**Важное ограничение:** геометрия схем и линии таблиц пока находятся в высококачественном растровом фоне, поэтому их нельзя редактировать как отдельные PowerPoint-линии. Редактируются текст и ячейки таблиц. Следующий возможный этап — отдельный конвертер PDF path → native PowerPoint shapes и многослайдовые документы.

## Windows / PowerShell

Обновить и установить PDF-зависимость в существующем окружении:

```powershell
git switch feature/native-drawing-conversion
git pull
.\.venv-vl\Scripts\python.exe -m pip install "PyMuPDF>=1.26.4,<2"
.\run-vl.ps1
```

Выберите PDF в главном окне; режим **«Цифровой PDF · структура без OCR»** включится автоматически. Если файл многостраничный, укажите номер страницы. Нажмите «Извлечь PDF → PPTX». Не нужны API-ключ и GPU.

Для видимого редактирования выбирайте **«Видимые надписи · как OCR»** (по умолчанию). Если GOSTTypeA недоступен, внешний вид текста PowerPoint будет отличаться, хотя оригинальная подложка полностью сохранена.

Вариант **«Точный оригинал · невидимые редактируемые слои»** выглядит в точности как исходный PDF и содержит полноценные редактируемые строки и ячейки для CAT. **Важно:** текстовые объекты визуально прозрачны, поэтому изменения после CAT не станут видимыми автоматически. Для финального переведённого PPTX требуется отдельный экспорт с видимыми наложениями.

CLI:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\digital.pdf" --ocr-engine native_pdf --pdf-page 1 --pdf-overlay-mode ocr_style
# Точный оригинальный вид, но невидимые редактируемые строки:
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\digital.pdf" --ocr-engine native_pdf --pdf-page 1 --pdf-overlay-mode source_exact
~~~

CLI:

```powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\digital.pdf" --ocr-engine native_pdf --pdf-page 1
```

Для PDF на несколько страниц можно последовательно повторить команду с `--pdf-page 2` и т. д. Используйте `--output` для явных имён PPTX; по умолчанию сохранённые файлы не перезаписываются.

## Критерии качества

- Подложка содержит весь оригинальный чертёж. В режиме «как OCR» исходные глифы под видимыми редактируемыми фреймами маскируются локально; остальная подложка не меняется. В режиме «Точный оригинал» текстовые наложения невидимы, оригинальные глифы отображаются без малейшей подмены.
- Многострочные поля остаются единой текстовой областью, пригодной для CAT; повторяющиеся номера и контакты не теряются.
- Короткие обозначения и цифровые коды доступны в редактируемых фреймах; в полной подложке они также остаются частью исходного рисунка.
- Структура таблиц совпадает с исходными линиями, объединённые ячейки в PPTX правильно расположены.
- Ошибки кодировки PDF, пропущенные при векторизации буквы и сложные таблицы явно помечаются для проверки.

Начальный тестовый набор генерирует векторный PDF с пересекающей подпись линией, многострочным блоком и таблицей с объединённой шапкой. Для настоящей работы особенно важно проверить PDF из CAD, InDesign и Office: некоторые из них визуально цифровые, но содержат символы как контуры — их распознать этим способом нельзя.
