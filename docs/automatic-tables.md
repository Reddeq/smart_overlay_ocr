# Автоматическое определение таблиц

## Изменение

В обычном локальном OCR сохранён поиск Paddle и расширен резервный поиск OpenCV. Раньше сетка, соединённая проводами с остальной схемой, становилась частью слишком большой связной компоненты и пропускалась. Теперь дополнительно рассматриваются пары вертикальных границ с совпадающими концами и повторяющимися горизонтальными строками. Одноколоночные таблицы допускаются при наличии как минимум четырёх строк. Для восстановления сетки и объединений используется прежняя проверка разделяющих линий.

Совпадение концов вертикальных границ отсеивает часть ложных сеток между соседними компонентами. Это эвристика для линованных неповёрнутых таблиц, а не универсальный анализ произвольной схемы. Пустые сетки без как минимум двух OCR-фрагментов не создаются как таблицы.

Кнопка «Найти таблицы» запускает тот же геометрический поиск для сохранённого проекта с OCR. Кандидат строится отдельно, проверяется и показывается до применения. Уже существующие таблицы не дублируются. Ручные исправления текста, оформление/геометрия, составные блоки, исключённые объекты и пропущенные OCR защищены. Сетка, которая затронула бы такие данные, пропускается целиком. Число отложенных кандидатов показывается в предпросмотре. Автоматический отступ обычного текста у границы новой таблицы может быть снят до исходной OCR-геометрии, как при первичном OCR; ручные координаты не перестраиваются.

Применение заменяет только принадлежащие таблице обычные блоки нативным объектом Table с ячейками. Сохраняются исходное изображение, Fragment.text, OCR ID, история исправлений и остальные объекты. Действуют существующие сохранение, редактор сетки и экспорт PPTX. Отпечаток проекта защищает от применения устаревшего результата. «Отменить применение» восстанавливает точный снимок до последнего применения, пока не началось следующее редактирование.

Нативные таблицы автоматически исключаются из экспериментальной группировки и уточнения нетабличного OCR. Ручные маски остаются запасным способом исключить пропущенные таблицы; проверка границ перед платным запуском сохраняется. Для текста ячеек и сеток добавлена отдельная операция [«VL-проверка таблиц»](table-review.md); она не выполняется внутри локального автопоиска.

## Локальная проверка реального листа

Использован неизменённый сохранённый Paddle OCR из предыдущих экспериментов: 1408×1024, 205 фрагментов, исходный результат без нативных таблиц. Поиск не получает ручные маски или эталон в качестве входа. После поиска границы сравнены с восемью ранее размеченными табличными зонами.

| Проверка | Результат |
|---|---|
| Найдено / отложено | 8 / 0 |
| Сетки | 2 × 9×2, 2 × 10×2, 4 × 11×1 |
| OCR внутри таблиц | 124 из 205 |
| Перекрытие с прежними ручными зонами (IoU) | 0,920–0,976 |
| Повторный поиск | 0 новых таблиц |
| Сохранение и повторное открытие | Проект идентичен кандидату |
| Локальный OCR с сохранёнными фрагментами и пустым ответом Paddle Tables | 8 таблиц через резервный поиск |
| Экспорт существующим генератором | 8 нативных `a:tbl` в PPTX |
| Новые платные запросы | 0 |

Ранее ручные маски исключали 125 OCR ID: одно соседнее обозначение частично пересекало широкую ручную область, но находится за найденной линией сетки. Этот текст остаётся отдельным объектом. Совпадение областей и корректность структуры проекта не доказывают точность текста или каждого объединения ячеек. Нужна проверка содержимого в редакторе. Повторный Paddle-инференс и платный VL в этой проверке не запускались.

Локальные артефакты находятся в игнорируемой папке `outputs/auto-tables/`: `report.json`, `detected.socr.json`, `detected.pptx`, снимки `editor.png` и `preview.png`. Исходный чертёж и его тексты в документацию не включены. Окна отрисованы настоящим Qt и визуально проверены; файл не открывался в Microsoft PowerPoint.

Автотесты на независимых синтетических изображениях проверяют соединённые проводами таблицы, одноколоночную сетку, отсутствие ложной таблицы между ними, объединённые ячейки, защиту правок/исключений, автоматические отступы текста, повторный поиск, сохранение, бюджет группировки и применение/отмену в GUI. Общие проверки также используют настоящий генератор PPTX.

Итоговая проверка: **206 тестов пройдено**, `compileall` и `git diff --check` без ошибок. Предупреждения Git о будущем преобразовании LF в CRLF относятся к настройкам рабочей копии; новых предупреждений Python или Qt при проверках нет.
