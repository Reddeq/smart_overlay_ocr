# VL-проверка таблиц

## Назначение и запуск

Отдельная кнопка «VL-проверка таблиц» работает с существующими нативными Table. Сначала выполните локальное OCR или «Найти таблицы». В подготовке отмечаются нужные таблицы, режимы проверки, порог уверенности Paddle и предел запросов. По умолчанию выбраны таблицы с отметкой проверки. Можно отправить только OCR, только структуру или оба вида заданий.

Низкоуверенный текст выбирается по исходным OCR-фрагментам внутри ячеек. Для каждого подходящего ID выполняется ровно одно чтение увеличенной области с соседним контекстом. Это позволяет применить исправленную строку к нужной ячейке и после принятого изменения структуры. Весь лист при чтении отдельного фрагмента не передаётся. Уверенность модели показывается только как её оценка, не используется как доказательство правильности и не включает замену автоматически.

## Структура

Для каждой выбранной таблицы отправляется её увеличенное изображение, исходная сетка, OCR ID, тексты и глобальные координаты. Модель возвращает полный список нормализованных границ строк/столбцов и ячеек с row/col, rowspan/colspan и принадлежностью OCR. Исправление текста отделено от этого задания.

До показа предложения проверяются строго возрастающие границы от 0 до 1, топология прямоугольных ячеек, полное покрытие сетки без пересечений, известность/уникальность/полнота OCR ID и попадание исходного OCR bbox в предложенную ячейку с допуском 3 px. Внешняя область таблицы остаётся прежней: расширение области с захватом новых надписей не выполняется. Если исходный OCR-фрагмент сам пересекает несколько ячеек и не помещается ни в одну, требуется ручная коррекция; модель не создаёт новые OCR ID и не разрезает исходник.

Проверка схемы и геометрии не подтверждает, что предложенные разделители соответствуют изображению. Все сетки и исправления текста в предпросмотре изначально выключены. Принятие сетки меняет локальную структуру; принятые OCR-чтения распределяются по финальным ячейкам по исходным ID. При неизменной принадлежности сохраняются ID и стиль существующих ячеек. При новой принадлежности стиль берётся у соответствующей исходной области; размер шрифта пересчитывается. Исходный растр, Fragment.text, координаты OCR, общий ID таблицы и остальные объекты сохраняются.

## Защита и применение

Исключённые таблицы, явно отмеченные ручные изменения, история исправлений, ручные/повторные OCR и отличающийся от исходного OCR текст ячеек защищены от этого прохода. Защищённая таблица обозначена в списке и не выбирается. Проверка консервативна: даже различие текста Paddle Table HTML и строк Paddle OCR может защитить таблицу. Для старых проектов ручное изменение текста выявляется сравнением; неотмеченное историческое изменение только геометрии/оформления нельзя всегда достоверно восстановить. Новые изменения в редакторе таблиц теперь явно отмечаются ручными, включая перестройку сетки без изменения текста.

До применения сравнивается полный отпечаток проекта. Применяются только выбранные предложения, в копии проекта, с проверкой целостности. Совпавший с исходником текст не требует применения. Исправления сохраняют before/after в существующей Correction; для структурных изменений сохраняются снимки таблицы и причина, confidence=0 означает отсутствие независимой оценки качества сетки. Принятая таблица остаётся `needs_review`. Последнее применение отменяется общей кнопкой «Отменить применение» до следующего редактирования.

После отмены или сетевого отказа доступны уже полученные предложения. Ошибочные ответы показываются с причиной, неизвестные/повторные/пропавшие ID не исправляются догадками. Сетевые сбои и ошибки оболочки API останавливают последующие запросы. Невалидный ответ одной сетки не уничтожает последующие независимые OCR-предложения. Обрезанный ответ не принимается и не повторяется.

## Маршрут и бюджет

Модель фиксирована: `qwen/qwen3-vl-8b-instruct`, Parasail без fallback, temperature=0, stream=false, json_object. Пользователь указывает HTTP-прокси активного VPN. Перед первым платным запросом выполняется публичная проверка через него, без ключа и изображения. Прямого обхода прокси нет, TLS проверяется. Приложение не запускает VPN и не меняет системные настройки.

Одна структура: максимум 4096 выходных токенов. Один OCR-фрагмент: 1024. До отправки показаны раздельное число запросов и общий предел выходных токенов. Пользователь подтверждает конкретный бюджет кнопкой отправки. Предел по умолчанию 20 запросов, настраивается до 100; превышение останавливает подготовку. Повторов нет. Тайм-ауты остаются из настроек. Отмена локального ожидания не гарантирует прекращение генерации или тарификации сервером.

## Проверка реализации и качества

На сохранённом реальном листе подготовка без сети дала 8 структурных запросов и 55 OCR-чтений при пороге 0,85: всего 63 запроса, максимум 89088 выходных токенов. Это расчёт, а не выполненная серия. Пользователь может выбрать меньше таблиц или отключить отдельный этап. Ключ и реальные платные запросы при разработке не использовались.

На независимом синтетическом примере намеренно неверная сетка 1×1 заменена проверенным предложением 4×3 с горизонтальным и вертикальным объединением. Выбранное исправление OCR попало в соответствующую итоговую ячейку; сохранение/открытие и настоящий экспорт PPTX прошли. Ответы в этих проверках контролируемые: они доказывают поведение клиента, не качество Qwen на реальном листе. Окна подготовки и результата отрисованы настоящим Qt и просмотрены; локальные снимки находятся в `outputs/table-review-qa/`.

Живую точность чтения и восстановления сетки нужно отдельно оценить по заранее подготовленному эталону и отдельно разрешённому бюджету. Этот новый режим не объявляется исправлением прежнего глобального Analysis. Формат проекта version=1, основной production-промпт, локальный OCR и генератор PPTX не менялись.

После изменения прошли **235 тестов**, `compileall` и `git diff --check`. Из них 29 новых проверок покрывают бюджет/порог, защиту правок, исправление ошибочной сетки, spans, полноту ID, недопустимую геометрию, отдельное применение OCR/структуры, сохранение и PPTX, остановку API-ошибки, отсутствие повторов, отмену, предпросмотр, устаревший снимок и откат. Ключи и содержимое невалидных полей не выводятся в диагностике схемы.

## Исправление отправки запросов

По пользовательскому сообщению воспроизведён `TypeError: Unexpected type for 'content', <class 'dict'>`. Новый табличный режим передавал словарь в `post_json`, тогда как транспорт передаёт готовое тело в httpx `content`. Ошибка возникала при построении POST, до отправки модели. Тело теперь явно сериализуется в JSON UTF-8, как в остальных VL-путях. Параметры модели, VPN, бюджет и отсутствие повторов не изменены.

Предыдущие тесты этого режима подменяли `post_json` и пропустили нарушение его контракта. Добавлены три проверки через настоящий `post_json` и httpx с MockTransport: только структура, только OCR и оба этапа. Все три сначала воспроизвели точную ошибку, затем прошли после исправления. Проверяются JSON-тело и кириллица, заголовки, явный прокси, публичный preflight без ключа, число POST без повторов и разбор предложений. Итог: **238 тестов пройдено**, `compileall` и проверка пробелов прошли. Реальные платные запросы для исправления не выполнялись; качество модели остаётся отдельной непроверенной задачей.
