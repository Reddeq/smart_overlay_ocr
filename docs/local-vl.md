# Локальный PaddleOCR-VL-1.6 — экспериментальный режим

## Назначение

Пользователь выбирает PaddleOCR-VL 1.6 · локально и распознаёт чертёж без стандартного PaddleOCR и OpenRouter. Движок локально выполняет анализ областей и распознаёт текст/таблицы, а приложение создаёт редактируемые объекты PowerPoint с оригинальным растром под ними.

**Ограничение:** PaddleOCR-VL возвращает геометрию **областей** (block_bbox), не гарантированные границы каждой строки или слова. На чертежах это может давать слишком крупные фреймы, которые затрут соседние линии. Все результаты помечаются для проверки. Точные координаты модель не гарантирует.

Табличный HTML преобразуется в нативные Table с rowspan/colspan. Границы столбцов и строк считываются из растровых линий, если согласуются с топологией. Иначе ячейки располагаются равномерно и отмечаются как непроверенные. Неверный HTML превращается в непроверенный текст, а не в придуманную сетку. Пустой результат не экспортируется в PPTX.

## Установка на Windows — отдельное окружение

В текущем приложении зафиксированы PaddleOCR 3.3.2 и PaddleX 3.3.13. Для PaddleOCR-VL 1.6 нужна обновлённая библиотека. Не меняйте основное окружение .venv — сначала создайте отдельное .venv-vl (Python 3.12 x64):

~~~powershell
py -3.12 -m venv .venv-vl
.\.venv-vl\Scripts\python.exe -m pip install --upgrade pip
.\.venv-vl\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-vl\Scripts\python.exe -m pip install --upgrade "paddleocr[doc-parser]>=3.6.0"
.\.venv-vl\Scripts\python.exe -m pip check
.\.venv-vl\Scripts\python.exe -c "from paddleocr import PaddleOCRVL; print('PaddleOCRVL available')"
~~~

Если PaddlePaddle CPU несовместим с установленной ОС или обновлённым PaddleOCR, установите подходящую CPU-сборку по официальной инструкции ниже. Не устанавливайте одновременно paddlepaddle и paddlepaddle-gpu.

Нужно сохранить имеющийся Node.js для генерации PPTX — через PATH или переменную SMART_OVERLAY_NODE.

Запуск GUI из тестового окружения (можно использовать короткий скрипт):

~~~powershell
.\run-vl.ps1
~~~

Или напрямую: .\.venv-vl\Scripts\python.exe -m smart_overlay

Запуск CLI на существующем файле:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\sample.png" --ocr-engine vl_local --vl-device cpu --vl-diagnostics ".\outputs\vl-local-test"
~~~

Замените sample.png на имя вашего изображения PNG/JPG/TIFF/BMP.

**Первый запуск скачивает веса моделей.** После скачивания сам инференс выполняется локально; передачи исходного чертежа в облако нет.

## CPU и GPU

Для RTX 2060 Super (6 ГБ VRAM, Compute Capability 7.5) начинайте с **CPU**, чтобы не упереться в CUDA/VRAM. Он может обрабатывать большой чертёж долго. Устройство GPU:0 доступно как экспериментальный вариант после установки совместимой GPU-сборки PaddlePaddle; модель и layout-детектор могут не поместиться в 6 ГБ. В этом режиме не используются vLLM, SGLang и FastDeploy — эти движки не поддерживают нативный Windows-запуск.

Официальные документы:
- [PaddleOCR-VL — установочные инструкции и Python API](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PaddleOCR-VL.en.md)
- [PaddlePaddle — установщик под CPU/GPU](https://www.paddlepaddle.org.cn/install/quick)

## Проверка

1. В главном окне выберите «PaddleOCR-VL 1.6 · локально (эксперимент)».
2. Выберите CPU.
3. Откройте чертёж из drawings/ и нажмите «Распознать → PPTX».
4. Сравните редактируемый PPTX с оригиналом, особенно многострочный текст, геометрию рамок, ячейки таблиц, мелкие обозначения и пропуски.
5. Для корректуры используйте «Исправить результат…».

Диагностика GUI сохраняется в каталоге:

    %LOCALAPPDATA%\SmartOverlayOCR\diagnostics\paddle-vl\<имя чертежа>-<ID запуска>\

Внутри:
- paddle-vl-result.json — оригинальный ответ модели с текстом;
- paddle-vl-summary.json — число распознанных/отклонённых блоков и причины;
- paddle-vl-boxes.png — оригинальный растр с рамками (оранжевый — текст, синий — таблицы).

Через CLI можно указать любой локальный каталог после --vl-diagnostics. Данные содержат тексты и изображения и не должны попадать в публичный репозиторий. Каталог outputs/ уже в .gitignore.

## Ограничения

- Одна картинка на один слайд. Нативный ввод PDF пока не добавлен.
- Это эксперимент: реальный инференс PaddleOCR-VL-1.6 на Windows и качество для схем **пока не подтверждены**.
- Не все классы layout принимаются: схемные графические объекты остаются на оригинальном растре; пропуски текстовых областей фиксируются в диагностике.
- Вставленные фреймы могут быть крупнее надписи, поэтому результат требует проверки до отправки в перевод.
- На обычный Smart OCR изменения этого режима не влияют; при проблемах с зависимостями используйте прежнюю .venv.
- Отмена поддерживается между этапами, но уже запущенный тяжёлый вызов VLM может завершаться не сразу.


## Если появляется ошибка «Нет пригодных текстовых областей»

На технических чертежах PP-DocLayoutV3 иногда классифицирует весь лист как область image. Режим use_ocr_for_image_block=True может распознать текст внутри изображения, но не гарантирует координат отдельных строк. Приложение намеренно не рисует один большой непрозрачный фрейм поверх схемы.

Начиная с исправления диагностики, после неудачной попытки в каталоге запуска **всё равно** появляются:
- paddle-vl-result.json — полный сырой ответ модели (содержит конфиденциальный текст);
- paddle-vl-summary.json — статус failed, перечень классов и границ регионов, без распознанных фраз;
- paddle-vl-boxes.png — области модели поверх оригинального изображения.

Для поиска самого свежего отчёта после запуска:

~~~powershell
$root = Join-Path $env:LOCALAPPDATA 'SmartOverlayOCR\diagnostics\paddle-vl'
Get-ChildItem $root -Recurse -Filter paddle-vl-summary.json |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1 -ExpandProperty FullName
~~~

Результат summary позволит отличить ошибку конвертера от того, что модель видит только image/figure. Исходный чертёж и ранее созданные PPTX не изменяются. Прикладывать полный JSON без проверки на конфиденциальные данные не рекомендуется.


## Производительность: обработка по участкам (новая реализация)

Ранее приложение делило чертёж на перекрывающиеся участки. Этот способ теперь сохранён как **резервная стратегия --vl-strategy tiles**:

- размер участка — 896 × 896 px, перекрытие — 96 px;
- одинаковая модель загружается один раз на всё задание, не по одному разу на участок;
- максимальная генерация — 384 токена на вызов (может обрезать длинные таблицы);
- пропускаются только действительно пустые белые участки;
- лимит — 64 участка на изображение (при превышении ошибка, а не незаметный пропуск части чертежа);
- ограничение запуска модели — 300 с; распознавания одного участка — 180 с.

Это **не гарантирует ускорения суммарного CPU-инференса**, но сокращает размер отдельной задачи, делает работу наблюдаемой, останавливаемой и ограниченной. Инференс всё равно может оказаться медленным на CPU. На видеокарте нужен установленный GPU PaddlePaddle; переключатель «GPU» без этой сборки не ускорит работу.

Каждый завершённый участок атомарно сохраняется в каталоге диагностики (даже если потом нажать «Отменить»):
- paddle-vl-tiles.json — план геометрических участков;
- tile-0000.json, tile-0001.json и т. д. — реальные промежуточные ответы;
- paddle-vl-progress.json — статус, число завершённых участков и информация об ошибках;
- paddle-vl-worker.log — локальный журнал модели.

После **успешного** завершения всех участков сохраняются общий paddle-vl-result.json, paddle-vl-summary.json и paddle-vl-boxes.png. При отмене/тайм-ауте завершённые результаты останутся на диске, но PPTX **не создаётся из неполных данных**.

Кнопка «Отменить» теперь прерывает отдельный вычислительный процесс, а не ждёт завершения его тяжёлого вызова. Существующие PPTX и оригинал не изменяются.

### CLI: регулировка производительности

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\sample.png" --ocr-engine vl_local --vl-device cpu --vl-tile-size 640 --vl-max-new-tokens 256 --vl-tile-timeout 120 --vl-diagnostics ".\outputs\vl-test"
~~~

Размер участка можно задать от 384 до 2048 px. Уменьшение размера снижает нагрузку одного вызова, но увеличивает число вызовов, а иногда ухудшает контекст. Сокращение числа токенов ускоряет генерацию, но может обрезать длинные тексты. Слишком большие чертежи могут превышать лимит участков — в таком случае используйте большее значение --vl-tile-size, подготовьте отдельную страницу или укажите --vl-max-tiles.

**Ограничение точности:** пересекающиеся участки объединяются по исходным пиксельным координатам. Дубли на границах подавляются по области ответственности; текст, который пересекает границу двух участков, может быть неполным. Эти места требуют визуальной проверки и фиксируются в диагностике.


## Детектор текста → локальная VL (новый режим по умолчанию)

В режиме PaddleOCR-VL теперь по умолчанию используется стратегия detect:

1. TextDetection с моделью PP-OCRv5_mobile_det находит многоугольники надписей, **не читая символы**.
2. PaddleOCR-VL-1.6 распознаёт небольшие вырезки с выключенной детекцией макета (use_layout_detection=False, prompt_label="ocr").
3. Координаты и поворот фреймов берутся от детектора, не из приблизительных блоков VL.
4. OpenCV пытается восстановить линованные таблицы из найденной сетки и распознанных строк.

Оба этапа выполняются полностью локально. При первом запуске может потребоваться дополнительная загрузка модели детекции.

Ограничения по умолчанию: максимум 80 строк на изображение, 128 новых токенов на строку, до 45 секунд на первую строку, до 60 на последующие и общий лимит 480 секунд после загрузки VL-модели. Превышение лимитов останавливает задачу без создания неполного PPTX. Непрочитанные надписи остаются на оригинальном растре, а их список фиксируется в отчёте.

**Одна строка всё ещё обрабатывается 0.9B-моделью.** Для длинных чертежей много коротких вызовов могут оказаться медленнее обычного OCR. Запустите бенчмарк до полноценного теста.

### Бенчмарк одной строки (без PPTX)

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay benchmark-vl ".\drawings\YOUR_DRAWING.png" --device cpu --timeout 45
~~~

Замените YOUR_DRAWING.png именем вашего изображения.

Команда измеряет отдельно загрузку детектора, его работу, загрузку PaddleOCR-VL и инференс **одной** строки. На инференс установлен жёсткий лимит, при тайм-ауте дочерний процесс завершается. Отчёт paddle-vl-benchmark.json содержит время, размер вырезки, количество найденных строк и наличие текста.

При наличии установленной GPU-сборки PaddlePaddle можно повторить с --device gpu:0. Видеокарте RTX 2060 Super с 6 ГБ может не хватить памяти; CUDA: False означает, что переключение GPU не ускорит модель.

Если одна строка распознаётся достаточно быстро:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\YOUR_DRAWING.png" --ocr-engine vl_local --vl-strategy detect --vl-device cpu --vl-max-regions 100
~~~

Старый вариант остался для сравнения: --vl-strategy tiles.

В диагностике сохраняются paddle-vl-regions.json с координатами и уверенностью детекции, **paddle-vl-detected.png** со всеми найденными текстовыми областями, region-XXXX.json с ответом VL по каждой строке, paddle-vl-progress.json и paddle-vl-worker.log. На отдельных строках с неизвестной ориентацией или за границами оригинала результат помечается для проверки. Таблицы определяются по линиям OpenCV и также требуют проверки.

Не считать эту реализацию проверенной, пока не получены реальные замеры Windows и оценка качества текста/PPTX на нескольких чертежах.

## Гибридный OCR v5 + v6 + пакетная локальная VL

Новый гибридный режим использует **одну детекцию**, затем PP-OCRv5 и дополнительную модель распознавания на тех же строках. PP-OCRv6_medium_rec покрывает 50 языков (китайский, английский, японский, латинская письменность), но **не покрывает кириллицу, арабский или корейский**. Для этих письменностей используются специализированные PP-OCRv5 и варианты подготовки строк.

Два варианта изображения — увеличение мелкого текста и повышение контраста. Оригинальные координаты, ID и структуры таблиц **не меняются**. Автоматически выбирается только безопасный кандидат при крайне низкой уверенности; по умолчанию OCR-консенсус сохраняется как предложение. Строки, где модели расходятся, помечаются для проверки.

Второй этап — максимум **один пакет из восьми** пронумерованных вырезок в PaddleOCR-VL-1.6. Это эксперимент: VL может неправильно скопировать номера, пропустить строки или слить текст. Сопоставление принимается только если один ответ содержит **все номера** в точном порядке без лишних строк. Не подтверждённые ответы не переписывают PPTX. На CPU ограничение обработки одного пакета по умолчанию 160 секунд; при превышении применяется основной OCR. Это время не гарантирует успешного чтения пакета.

Пакетные VL-вызовы необязательны: их можно отключить параметром `--ensemble-only`. Для высокоуверенного ошибочного OCR возможно автоприменение только если независимая PP-OCRv6 и полностью сопоставленный VL дали один и тот же близкий вариант без изменений чисел/кодов. Автоматическая правка **всегда** остаётся отмеченной для ручной проверки.

### Запуск Windows

~~~powershell
git pull
.\run-vl.ps1
~~~

В интерфейсе выберите **«Smart OCR · два распознавателя + VL»**. Для предварительной диагностики быстрее использовать CLI:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\sample.png" --ocr-engine hybrid_local --languages ru,en --ensemble-only
~~~

Для ограниченной пакетной VL-проверки:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\sample.png" --ocr-engine hybrid_local --languages ru,en --ensemble-batch-size 8 --ensemble-max-batches 1
~~~

Новые файлы диагностики в `%LOCALAPPDATA%\SmartOverlayOCR\diagnostics\paddle-vl-hybrid\<имя>-<ID>`:

- `ocr-ensemble.json` — все OCR ID, исходные тексты, повторы, расхождения и итоговое чтение
- `ocr-ensemble-summary.json` — статистика покрытия, расхождений, попыток VL и применённых исправлений
- `vl-batch-00.png` — пронумерованные вырезки (при запуске VL)
- `vl-batch-00.json` — сырой ответ + статус проверки всех номеров
- `ocr-ensemble-vl-audit.json` — принятые и отклонённые VL-предложения
- `paddle-vl-progress.json`, `paddle-vl-worker.log` — время, ошибки и прерывания

Для измерения реального улучшения подготовьте ручной эталон:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay evaluate-ocr "ПУТЬ\ocr-ensemble.json" --make-template "ПУТЬ\truth.csv"
# Заполните колонку truth для нужных OCR ID, не копируйте туда ответ модели
.\.venv-vl\Scripts\python.exe -m smart_overlay evaluate-ocr "ПУТЬ\ocr-ensemble.json" --truth "ПУТЬ\truth.csv"
~~~

Оценка использует CER (число ошибочных символов / число символов эталона) и exact-match на вручную размеченных фрагментах. Кандидат может иметь меньшее покрытие, чем основной OCR; сравнивайте одинаковые ID. Создание PPTX само по себе **не показатель точности**.

### Ограничения

- Модель PP-OCRv6 может не скачаться/не запуститься в закреплённом старом окружении; используйте отдельную `.venv-vl` и смотрите `ocr-ensemble.json`
- Вырезки не заменяют детектор: **полностью пропущенные строки не восстанавливаются**
- Для Cyrillic альтернативы PP-OCRv5 с разной обработкой не являются независимыми архитектурами
- Блоки с числовыми техническими кодами не подвергаются неконтролируемой коррекции
- Пакетная VL-проверка с `prompt_label="ocr"` ещё не подтверждена реальным прогоном на Windows и может вернуть текст без номеров; такой ответ не применяется
- Точность таблиц, многострочных блоков и итоговых оверлеев нужно проверять отдельно от CER
- Все диагностические файлы содержат конфиденциальные исходные фразы и остаются локальными
