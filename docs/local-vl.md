# Локальный PaddleOCR-VL-1.6 — экспериментальный режим

## Назначение

Пользователь выбирает PaddleOCR-VL 1.6 · локально и распознаёт чертёж без стандартного PaddleOCR и OpenRouter. Движок локально выполняет анализ областей и распознаёт текст/таблицы, а приложение создаёт редактируемые объекты PowerPoint с оригинальным растром под ними.

**Ограничение:** PaddleOCR-VL возвращает геометрию **областей** (block_bbox), не гарантированные границы каждой строки или слова. На чертежах это может давать слишком крупные фреймы, которые затрут соседние линии. Все результаты помечаются для проверки. Точные координаты модель не гарантирует.

Табличный HTML преобразуется в нативные Table с rowspan/colspan. Границы столбцов и строк считываются из растровых линий, если согласуются с топологией. Иначе ячейки располагаются равномерно и отмечаются как непроверенные. Неверный HTML превращается в непроверенный текст, а не в придуманную сетку. Пустой результат не экспортируется в PPTX.

## Установка на Windows — отдельное окружение

В текущем приложении зафиксированы PaddleOCR 3.3.2 и PaddleX 3.3.13. Для PaddleOCR-VL 1.6 нужна обновлённая библиотека. Не меняйте основное окружение .venv — сначала создайте отдельное .venv-vl (Python 3.12 x64):

~~~powershell
py -3.12 -m venv .venv-vl
.\.venv-vl\Scripts\python.exe -m pip install --upgrade pip
.\.venv-vl\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-vl\Scripts\python.exe -m pip install --upgrade "paddleocr[doc-parser]>=3.6.0"
.\.venv-vl\Scripts\python.exe -m pip check
.\.venv-vl\Scripts\python.exe -c "from paddleocr import PaddleOCRVL; print('PaddleOCRVL available')"
~~~

Если PaddlePaddle CPU несовместим с установленной ОС или обновлённым PaddleOCR, установите подходящую CPU-сборку по официальной инструкции ниже. Не устанавливайте одновременно paddlepaddle и paddlepaddle-gpu.

Нужно сохранить имеющийся Node.js для генерации PPTX — через PATH или переменную SMART_OVERLAY_NODE.

Запуск GUI из тестового окружения:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay
~~~

Запуск CLI на существующем файле:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\sample.png" --ocr-engine vl_local --vl-device cpu --vl-diagnostics ".\outputs\vl-local-test"
~~~

Замените sample.png на имя вашего изображения PNG/JPG/TIFF/BMP.

**Первый запуск скачивает веса моделей.** После скачивания сам инференс выполняется локально; передачи исходного чертежа в облако нет.

## CPU и GPU

Для RTX 2060 Super (6 ГБ VRAM, Compute Capability 7.5) начинайте с **CPU**, чтобы не упереться в CUDA/VRAM. Он может обрабатывать большой чертёж долго. Устройство GPU:0 доступно как экспериментальный вариант после установки совместимой GPU-сборки PaddlePaddle; модель и layout-детектор могут не поместиться в 6 ГБ. В этом режиме не используются vLLM, SGLang и FastDeploy — эти движки не поддерживают нативный Windows-запуск.

Официальные документы:
- [PaddleOCR-VL — установочные инструкции и Python API](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PaddleOCR-VL.en.md)
- [PaddlePaddle — установщик под CPU/GPU](https://www.paddlepaddle.org.cn/install/quick)

## Проверка

1. В главном окне выберите «PaddleOCR-VL 1.6 · локально (эксперимент)».
2. Выберите CPU.
3. Откройте чертёж из drawings/ и нажмите «Распознать → PPTX».
4. Сравните редактируемый PPTX с оригиналом, особенно многострочный текст, геометрию рамок, ячейки таблиц, мелкие обозначения и пропуски.
5. Для корректуры используйте «Исправить результат…».

Диагностика GUI сохраняется в каталоге:

    %LOCALAPPDATA%\SmartOverlayOCR\diagnostics\paddle-vl\<имя чертежа>\

Внутри:
- paddle-vl-result.json — оригинальный ответ модели с текстом;
- paddle-vl-summary.json — число распознанных/отклонённых блоков и причины;
- paddle-vl-boxes.png — оригинальный растр с рамками (оранжевый — текст, синий — таблицы).

Через CLI можно указать любой локальный каталог после --vl-diagnostics. Данные содержат тексты и изображения и не должны попадать в публичный репозиторий. Каталог outputs/ уже в .gitignore.

## Ограничения

- Одна картинка на один слайд. Нативный ввод PDF пока не добавлен.
- Это эксперимент: реальный инференс PaddleOCR-VL-1.6 на Windows и качество для схем **пока не подтверждены**.
- Не все классы layout принимаются: схемные графические объекты остаются на оригинальном растре; пропуски текстовых областей фиксируются в диагностике.
- Вставленные фреймы могут быть крупнее надписи, поэтому результат требует проверки до отправки в перевод.
- На обычный Smart OCR изменения этого режима не влияют; при проблемах с зависимостями используйте прежнюю .venv.
- Отмена поддерживается между этапами, но уже запущенный тяжёлый вызов VLM может завершаться не сразу.
