# Полное облачное распознавание чертежа (эксперимент)

Этот режим **не запускает PaddleOCR, PP-OCRv5, PP-OCRv6 или локальную PaddleOCR-VL**. Мультимодальная модель OpenRouter читает **само изображение** и возвращает текст/таблицы с координатами. Создаётся PPTX с оригинальным изображением под редактируемыми объектами.

## Запуск из приложения

1. В «Настройки» укажите **API-ключ OpenRouter**, при необходимости HTTP-прокси вашего активного Xray/VPN и модель полного облачного OCR (`google/gemini-2.5-pro` по умолчанию). Ключ не сохраняется в файл настроек.
2. Выберите **«Облако · весь чертёж (эксперимент)»**. В этом режиме переключатель языков и выбор CPU/GPU не используются.
3. Выберите исходное изображение PNG/JPEG/TIFF/BMP (не прежний OCR-PPTX) и нажмите «Распознать → PPTX».
4. Подтвердите отправку изображения во внешний сервис. Без подтверждения запросов не будет.
5. Сравните оригинал и PPTX: точность кириллицы, электрические обозначения, таблицы, расположение рамок и объединённые ячейки.

**Важно:** исходный чертёж будет передан OpenRouter и выбранному провайдеру модели. Убедитесь, что у вас есть право передавать документ третьим лицам. API **платный**, стоимость зависит от модели, размера изображения и числа выходных токенов. Факт отмены после отправки не гарантирует отсутствие списаний.

## Почему изображение делится на фрагменты

Полный лист на ~200 надписей трудно описать одним большим JSON-ответом. Поэтому режим **не использует локальный текстовый детектор**, но разрезает **сам растр** на сбалансированные области. Теперь размер области по умолчанию — до **640 × 640 пикселей**, перекрытие соседних областей — около **48 пикселей**. Для чертежа **1408 × 1024 получается 6 областей примерно по 502 × 536**, вместо прежних четырёх участков 736 × 544. Это больше платных запросов; зато на каждом участке заметно меньше текста. Итоговое число платных запросов показывается в окне подтверждения ещё до отправки. Максимум — 8 запросов, до 240 секунд на запрос (оба значения настраиваются).

Каждый запрос требует JSON с независимыми текстовыми фреймами и HTML для настоящих линованных таблиц. Для Gemini теперь используются координаты **XYXY, нормализованные к 0–1000** по ширине и высоте отправленного фрагмента. Приложение переводит их в пиксели исходного листа; старые ответы, где координаты выходят за границы фрагмента, дополнительно проверяются на нормализованную шкалу. Ответы с явно указанной пиксельной системой координат обрабатываются без масштабирования. Дубли в перекрытиях подавляются по области ответственности. Таблицы с поддерживаемой HTML-структурой становятся нативными PowerPoint-таблицами; неуверенные позиции остаются с отметкой проверки. Мелкие отдельно стоящие коды/числа по действующему правилу сохраняются на исходном растре.

**Ограничения:** даже сильная модель может придумать символы, неверно различить латиницу и кириллицу, выдать приблизительные координаты или ошибиться на границе двух фрагментов. Нельзя считать успешный экспорт гарантией точности. При слишком большом числе ошибочных bbox, пустой обработке или обрезанном ответе PPTX **не создаётся**. Дорогие запросы **не повторяются автоматически**. Все текстовые области помечаются как требующие ручной проверки.

## Командная строка (Windows)

В PowerShell из каталога репозитория:

~~~powershell
$env:OPENROUTER_API_KEY = "ВАШ_КЛЮЧ"
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\01-02.png" --ocr-engine cloud_full --consent-api --cloud-model "google/gemini-2.5-pro" --proxy "http://127.0.0.1:10809"
~~~

Замените `01-02.png` на имя исходного файла. Подойдёт и основная `.venv`, если там установлены базовые зависимости; VL-модели не нужны. Переменная окружения используется только текущим процессом PowerShell и не записывается в Git.

При необходимости можно ограничить стоимость и размеры:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\01-02.png" --ocr-engine cloud_full --consent-api --cloud-max-requests 6 --cloud-tile-size 640 --cloud-max-tokens 8192 --cloud-timeout 240 --proxy "http://127.0.0.1:10809"
~~~

Модели с другим API могут не поддерживать JSON-ответы в этом режиме; в таком случае программа сохранит ошибку, а не молча переключится на PaddleOCR. Пример модели для испытания — [Gemini 2.5 Pro на OpenRouter](https://openrouter.ai/google/gemini-2.5-pro). Перед запуском проверьте актуальную стоимость.

## Исправление `finish_reason=length`

Если провайдер завершает ответ с `finish_reason=length`, значит лимита ответных токенов не хватило на полный JSON. Это может происходить и потому, что **токены рассуждений Gemini 2.5 учитываются внутри `max_tokens`**. Для Gemini 2.5 Pro отправляется `reasoning: {"max_tokens":1024}` при общем лимите `max_tokens=8192`. Этот параметр **не** отправляется другим моделям автоматически. Ограничение рассуждений — не гарантия успешного OCR и зависит от поддержки провайдера.

Ответ модели теперь запрашивается в компактном виде `{"coordinate_system":"normalized_1000_xyxy","blocks":[["t",x0,y0,x1,y1,"текст"],["h",x0,y0,x1,y1,"<table>...</table>"]]}`. Старый объектный формат ответа тоже принимается. Это уменьшает расход токенов на повторяющиеся ключи, не отказываясь от редактируемых надписей и таблиц.

При обрезанном ответе запрос **не повторяется автоматически**: он уже мог быть оплачен. `cloud-ocr-error.json` сохраняет `finish_reason`, доступные значения `usage`, лимиты токенов, номер области и причину остановки. После просмотра отчёта пользователь сам принимает решение о новом платном запуске.

### Повторный тест того же чертежа

~~~powershell
git pull
.\run-vl.ps1
~~~

Выберите **«Облако · весь чертёж (эксперимент)»**. В окне подтверждения должно быть **6 запросов** для изображения 1408 × 1024. Это больше предыдущих четырёх: цена может возрасти, хотя каждый ответ теперь короче. Просмотрите стоимость и подтвердите отправку, если готовы к новому платному опыту.

Чтобы через CLI явно проверить новые параметры:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\01-02.png" --ocr-engine cloud_full --consent-api --cloud-tile-size 640 --cloud-max-requests 6 --cloud-max-tokens 8192 --cloud-reasoning-tokens 1024 --proxy "http://127.0.0.1:10809"
~~~

Замените имя файла и при необходимости задайте `OPENROUTER_API_KEY` в текущем PowerShell; не копируйте ключ в общедоступные логи.

### Что показал реальный повторный запуск

На чертеже 1408 × 1024 первые настройки 768/64 привели к **4 запросам**. Область №1 завершилась с **32 блоками**, но **22 блока** имели координаты за пределами картинки 736 × 544 при буквальном пиксельном прочтении. Например, `[136,724,304,828]` преобразуется из шкалы 0–1000 в приблизительно `[100,394,224,450]` пикселей, что соответствует расположению нижней левой подписи. Поэтому изменён **формат системы координат**, а не просто размер изображения.

Область №2 была обрезана после 8156 выходных токенов при лимите 8192; провайдер сообщил **1402 токена рассуждений**, несмотря на заданный лимит 1024. Следовательно, на фактическое соблюдение ограничения рассуждений нельзя полагаться. Более мелкие изображения и компактный JSON должны снижать вероятность нового `finish_reason=length`, но не гарантируют успеха.

Ни один ранее оплаченный запрос **не повторяется автоматически**. Новая сетка 640/48 несовместима со старым первым успешно завершённым фрагментом 736 × 544, поэтому при полном повторном запуске чертёж будет отправлен заново только с отдельным подтверждением.

## Диагностика и приватность

Локально создаётся каталог `%LOCALAPPDATA%\SmartOverlayOCR\diagnostics\cloud-full\<имя чертежа>-<ID>`:

- `cloud-ocr-plan.json`: конфигурация модели, число фрагментов и координаты;
- `cloud-ocr-00.json`, `cloud-ocr-01.json`, …: валидированные ответы для каждого фрагмента;
- `cloud-ocr-merged.json`: итоговые координаты и текст в исходных пикселях;
- `cloud-ocr-summary.json`: количество запросов, доступные показатели токенов/стоимости и исключённые области;
- `cloud-ocr-error.json`: причина неудачи без API-ключа.

Эти файлы могут содержать **конфиденциальный текст чертежа**. Они не добавляются в Git автоматически. Папка `drawings/` также игнорируется Git.

Если у вас остался только прежний `.pptx`, используйте исходный растр/скан чертежа: в приложении пока поддерживается ввод PNG/JPEG/TIFF/BMP, а не распознавание текстовых фреймов PPTX.
