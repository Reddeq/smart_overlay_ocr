# Полное облачное распознавание чертежа (эксперимент)

Этот режим **не запускает PaddleOCR, PP-OCRv5, PP-OCRv6 или локальную PaddleOCR-VL**. Мультимодальная модель OpenRouter читает **само изображение** и возвращает текст/таблицы с координатами. Создаётся PPTX с оригинальным изображением под редактируемыми объектами.

## Запуск из приложения

1. В «Настройки» укажите **API-ключ OpenRouter**, при необходимости HTTP-прокси вашего активного Xray/VPN и модель полного облачного OCR (`google/gemini-2.5-pro` по умолчанию). Ключ не сохраняется в файл настроек.
2. Выберите **«Облако · весь чертёж (эксперимент)»**. В этом режиме переключатель языков и выбор CPU/GPU не используются.
3. Выберите исходное изображение PNG/JPEG/TIFF/BMP (не прежний OCR-PPTX) и нажмите «Распознать → PPTX».
4. Подтвердите отправку изображения во внешний сервис. Без подтверждения запросов не будет.
5. Сравните оригинал и PPTX: точность кириллицы, электрические обозначения, таблицы, расположение рамок и объединённые ячейки.

**Важно:** исходный чертёж будет передан OpenRouter и выбранному провайдеру модели. Убедитесь, что у вас есть право передавать документ третьим лицам. API **платный**, стоимость зависит от модели, размера изображения и числа выходных токенов. Факт отмены после отправки не гарантирует отсутствие списаний.

## Почему изображение делится на фрагменты

Полный лист на ~200 надписей трудно описать одним большим JSON-ответом. Режим **не использует локальный текстовый детектор**, но разрезает **сам растр** на перекрывающиеся квадраты 1024 × 1024 пикселя. Для чертежа 1408 × 1024 обычно получится два облачных запроса. Это сделано ради мелкого текста, чтобы исходник не был уменьшен до нечитаемого размера. Пользователь задаёт верхнюю границу **8 запросов** (по умолчанию) и максимальную длительность **240 секунд на запрос**.

Каждый запрос требует JSON с независимыми текстовыми фреймами и HTML для настоящих линованных таблиц. Координаты должны быть в **пикселях текущего фрагмента**; программа строго проверяет их, преобразует к исходному размеру листа и убирает повторные рамки из перекрытий. Таблицы с поддерживаемой HTML-структурой становятся нативными PowerPoint-таблицами; неуверенные позиции остаются с отметкой проверки. Мелкие отдельно стоящие коды/числа по действующему правилу сохраняются на исходном растре.

**Ограничения:** даже сильная модель может придумать символы, неверно различить латиницу и кириллицу, выдать приблизительные координаты или ошибиться на границе двух фрагментов. Нельзя считать успешный экспорт гарантией точности. При слишком большом числе ошибочных bbox, пустой обработке или обрезанном ответе PPTX **не создаётся**. Дорогие запросы **не повторяются автоматически**. Все текстовые области помечаются как требующие ручной проверки.

## Командная строка (Windows)

В PowerShell из каталога репозитория:

~~~powershell
$env:OPENROUTER_API_KEY = "ВАШ_КЛЮЧ"
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\01-02.png" --ocr-engine cloud_full --consent-api --cloud-model "google/gemini-2.5-pro" --proxy "http://127.0.0.1:10809"
~~~

Замените `01-02.png` на имя исходного файла. Подойдёт и основная `.venv`, если там установлены базовые зависимости; VL-модели не нужны. Переменная окружения используется только текущим процессом PowerShell и не записывается в Git.

При необходимости можно ограничить стоимость и размеры:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert ".\drawings\01-02.png" --ocr-engine cloud_full --consent-api --cloud-max-requests 3 --cloud-tile-size 1024 --cloud-max-tokens 8192 --cloud-timeout 240 --proxy "http://127.0.0.1:10809"
~~~

Модели с другим API могут не поддерживать JSON-ответы в этом режиме; в таком случае программа сохранит ошибку, а не молча переключится на PaddleOCR. Пример модели для испытания — [Gemini 2.5 Pro на OpenRouter](https://openrouter.ai/google/gemini-2.5-pro). Перед запуском проверьте актуальную стоимость.

## Диагностика и приватность

Локально создаётся каталог `%LOCALAPPDATA%\SmartOverlayOCR\diagnostics\cloud-full\<имя чертежа>-<ID>`:

- `cloud-ocr-plan.json`: конфигурация модели, число фрагментов и координаты;
- `cloud-ocr-00.json`, `cloud-ocr-01.json`, …: валидированные ответы для каждого фрагмента;
- `cloud-ocr-merged.json`: итоговые координаты и текст в исходных пикселях;
- `cloud-ocr-summary.json`: количество запросов, доступные показатели токенов/стоимости и исключённые области;
- `cloud-ocr-error.json`: причина неудачи без API-ключа.

Эти файлы могут содержать **конфиденциальный текст чертежа**. Они не добавляются в Git автоматически. Папка `drawings/` также игнорируется Git.

Если у вас остался только прежний `.pptx`, используйте исходный растр/скан чертежа: в приложении пока поддерживается ввод PNG/JPEG/TIFF/BMP, а не распознавание текстовых фреймов PPTX.
