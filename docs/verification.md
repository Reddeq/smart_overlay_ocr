# Проверка 12 ноября 2026

Окружение: Windows x64, Python 3.12.14, PaddleOCR 3.3.2, PaddlePaddle 3.2.2 CPU, PaddleX 3.3.13, PySide6 6.8.3, Node.js 24.22.1, PptxGenJS 4.0.1. Установлены настоящие зависимости; `pip check` не обнаружил несовместимостей. Полный список фиксирован в `requirements-lock.txt`.

## Выполнено

- 37 автоматических проверок на момент подготовки отчёта: структура и происхождение OCR, геометрия поворотов, форматы/EXIF и неизменность исходника, проекты, таблицы и spans, обнаружение пропущенной таблицы OpenCV, клиент VL, кеш/повторы/согласие/отказ авторизации, увеличенная проверка сомнительной ячейки, локальный режим и отказ Smart, GUI и оформление ячеек, XML настоящей презентации. Компиляция модулей Python прошла.
- Синтетическая схема `examples/technical-demo.png`: настоящий OCR нашёл 16 фрагментов с уверенностью примерно 0.94–1.00. Конвейер разметки страницы классифицировал схему как изображение и пропустил встроенную таблицу. Поиск сеток OpenCV восстановил таблицу 4×3, объединение трёх ячеек заголовка и вертикальное объединение двух строк. Текст всех девяти логических ячеек совпал с эталоном. Таблица помечена для ручной проверки.
- Повторный локальный прогон с загруженными моделями: около 20 секунд, включая инициализацию моделей. Дополнительный прогон при ограниченном сетевом доступе успешно использовал кеш. Проверка подключения к серверам моделей отключена поддерживаемым параметром PaddleX перед импортом.
- Создан `examples/technical-demo.pptx` из явно обозначенной эталонной разметки. XML подтверждает один слайд нужных пропорций, исходное изображение без перекодирования, три редактируемых текста с собственной заливкой, нативную таблицу с горизонтальными/вертикальными объединениями и заданными высотами строк.
- Предпросмотр приложения проверен по снимку Qt, исправлены отсутствие шрифта в offscreen-среде и размеры боковых панелей. Тяжёлые операции вынесены из GUI-потока.

## Выбор табличного конвейера

Проверен запуск PP-StructureV3. В PaddleX 3.3.13 `layout_parsing/pipeline_v2.py` создаёт ChartRecognition независимо от `use_chart_recognition`; это привело к загрузке ненужной для проекта тяжёлой модели. Используется поддерживаемый `TableRecognitionPipelineV2`, который является тем же табличным подконвейером, с первичным OCR через `overall_ocr_res`, без повторной языковой модели. Автоориентация таблиц отключена. Выбор соответствует разрешённой ТЗ альтернативе PP-StructureV3.

## Не подтверждено

- Запросы к реальному OpenRouter: ключ и согласие на передачу изображений не предоставлены. Сетевой протокол и обработка ответов покрыты контролируемыми unit-тестами; качество живой модели не измерено.
- Приёмка на 5–10 разнообразных реальных схемах: таких входных файлов в задании нет. Не заявляются точность, полнота или экономия ручной работы на реальных данных.
- Проверка в установленном Microsoft PowerPoint: приложение запустилось через computer-use, но захват окна завершился `FrameArrived timed out`, действие по UI — `coordinate input geometry is unavailable`. Презентацию через этот интерфейс открыть и проверить не удалось. Требуется ручное открытие примера, проверка редактирования текста и ячеек, переносов, заливок, объединений и растрирования при 150 DPI.

Эталонный проект и пример PPTX не выдаются за результат Smart OCR. Тестовая презентация демонстрирует возможности генератора; полноценная приёмка качества требует живой VL-модели и реальных исходников.

## Изменения после пользовательской проверки

По журналу пользователя три ответа VL были отклонены общей проверкой схемы/геометрии. Невалидные ответы не сохранялись, поэтому установить точную причину этих ответов задним числом невозможно. Добавлены конкретные диагностические сообщения без значений невалидных полей и ключа, контекст исправления в повторном запросе, обработка внешнего JSON-блока Markdown и ошибок оболочки API. Ошибка кеширования корректного результата больше не инициирует повторный запрос.

По запросу пользователя разрешён экспорт непроверенных объектов: GUI показывает предупреждение с возможностью продолжения, CLI принимает `--allow-unreviewed`. Отметки проверки не снимаются, проверки целостности сохраняются. Изменение приоритета ручной проверки относительно первоначального ТЗ явно разрешено пользователем.

После этих изменений прошли **49 тестов**. Дополнительно проверены создание настоящего PPTX с непроверенными текстом и таблицей, сохранение запрета на повреждённые OCR-связи, подтверждение/отмена предупреждения в GUI, обратная связь при повторе VL, сокрытие входных значений в диагностике, пустые/обрезанные ответы и отказ записи кеша. Новые реальные API-запросы не выполнялись.

При следующем пользовательском запуске проявились отказы `VL не проверила все таблицы` и отсутствие Node.js в окружении GUI. Исправлено сохранение локальных таблиц с отметкой проверки при пропущенных VL-проверках; корректная группировка остального текста больше не отклоняется по этой причине. Избыточные группы, состоящие только из табличных OCR, не создают дублирующие фреймы; смешанные группы и неверные ссылки отклоняются.

Добавлен поиск Node.js вне `PATH`: локальный runtime `.runtime/node/node.exe`, стандартные каталоги установки Windows и явный `SMART_OVERLAY_NODE`. В текущем рабочем каталоге подготовлен локальный runtime из уже установленного Node.js 24.22.1; SHA-256 копии совпал с исходным файлом. Бинарник исключён из Git. Выполнен настоящий экспорт `outputs/no-path-export.pptx` с пустым `PATH`; ZIP презентации содержит ожидаемый слайд. После исправлений прошли **57 тестов**, компиляция Python и `pip check`. Дополнительно проверен весь Smart-конвейер на контролируемом ответе без проверки таблицы. Реальный внешний API повторно не вызывался.

После сообщения о долгом ожидании проверено соединение с OpenRouter без пользовательского ключа и изображения: DNS разрешился за 0.03 секунды, публичный `/api/v1/models` ответил `200` за 0.89 секунды; выбранная модель присутствовала в ответе. Это не подтверждает успешную генерацию с ключом пользователя. В прежнем коде отсутствовали этапы сетевого прогресса, один сокетный тайм-аут составлял 120 секунд и мог повторяться трижды.

HTTP-транспорт заменён на httpx 0.28.1 (эта версия уже была установлена транзитивно; теперь зафиксирована и как прямая зависимость). Добавлены этапы и таймер ожидания, отдельный тайм-аут подключения, полный срок попытки, прекращение автоматических повторов после локального тайм-аута и отмена Smart OCR без утраты локального результата. Проверено реальное получение `401` на запрос с заведомо недействительным тестовым токеном, без изображения и генерации, примерно за 0.5 секунды. Подтверждена последовательность DNS/TCP → TLS → отправка → запрос отправлен → HTTP-ответ; CONNECT к прокси не считается отправкой изображения.

Прошли **65 тестов**, включая остановку зависшего ответа с постоянно поступающими пробелами по полному сроку, запрет повторов тайм-аута, запрет перенаправления ключа, отчёт этапов без приватных метаданных, отмену реального Smart/HTTP-конвейера в QThread на контролируемом транспорте и восстановление доступности экспорта. Проверки Python и `pip check` также прошли. В тестах Qt явно обрабатываются отложенные удаления объектов перед закрытием тестового окна. Платный запрос с реальным ключом и пользовательской схемой не выполнялся; причина задержки именно той генерации остаётся неподтверждённой.

По следующему журналу пользователя ответ VL трижды отклонялся из-за пропущенных OCR ID. Исправлено принятие частичных результатов: корректные группы сохраняются, непокрытые OCR восстанавливаются из локальных данных с отметкой проверки. Полностью пропущенный блок сохраняет ручные исправления и геометрию; рамка не получает повторный запас при форматировании. Если пропущена только часть блока, используется геометрия соответствующих исходных фрагментов. Низкая полнота ответа не выдаётся за успешную VL-проверку всех надписей.

Прошли **75 тестов**, включая весь Smart-конвейер с неполным HTTP-ответом (один запрос вместо трёх), сохранность текста и ручных правок, восстановление отдельной измеренной части, исключения и отсутствие дублирующих фреймов таблицы. Дубли, неизвестные ID и недопустимая геометрия по-прежнему отклоняются. Реальная генерация с пользовательским ключом не запускалась.

Следующий скриншот уточнил текущую причину: `Тайм-аут запроса: HTTP 200; получено 0.4 КБ (120 с)`. Это истечение общего срока получения ответа до завершения JSON, а не отказ геометрической валидации. По скриншоту нельзя установить, сколько времени провайдер потратил на очередь и сколько на генерацию.

Добавлены сохранение отклонённого/незавершённого ответа и контекста без ключа и изображения, а также команда `replay-vl` для локального воспроизведения проверки. Запись ограничена по размеру и числу слотов. При тайм-ауте сохраняются HTTP-код, Content-Type, число байтов, доступный ID генерации и полученный фрагмент ответа. Незавершённые данные не выдаются за готовую структуру.

Сокращены текстовое задание и JSON Schema: стили и ID ячеек остаются в приложении, неизменённый текст/ячейки не требуется повторять в ответе. На синтетическом примере текстовая часть пакета уменьшилась с 5868 до 2768 байт (52.8%); это не измерение ускорения реальной модели и не размер передаваемых изображений. Включён SSE-режим с разбором комментариев, фрагментов текста, завершающих событий, ошибок и usage. Лимит ответа задаётся настройкой; обрезанный ответ не вызывает повтор с тем же бюджетом.

Прошли **84 теста**: дополнительно проверены локальное воспроизведение ошибки и исправленного ответа без новых HTTP-вызовов, отсутствие ключа/изображения в диагностике, ограничения размера, компактный формат без потери текста/ячеек, UTF-8 и SSE-события на границах сетевых чанков, служебные комментарии, usage, ошибки и незавершённый поток. Ускорение и успешная генерация на пользовательской схеме через реальный провайдер пока не подтверждены. Платные запросы в ходе этой доработки не выполнялись.

Последующая локальная диагностика уточнила фактический ход пользовательского запуска 12 ноября (время Москвы): в 17:59:30 в кеш попал пустой `Analysis`, затем с 17:59:34 по 18:00:08 получены 13 корректных по схеме ответов `Reading`. Все 13 содержат заявленную моделью уверенность не ниже 0.95; это не независимая оценка их точности. Следующее уточнение остановилось на TLS-подключении за 10 секунд: `http_status: null`, `received_bytes: 0`, тип ответа `Reading`. Значит, проблема состояла не в полном отсутствии ответа модели: единичная ошибка дополнительного уточнения прерывала весь проход, а основной структурный ответ был пустым.

Исправлено сохранение частичного результата при ошибке уточнения: принятые изменения остаются, оставшиеся фрагменты отмечаются, последующие уточнения в этом проходе прекращаются. Добавлен отчёт числа обработанных фрагментов. Повторы тайм-аута разрешены только при явном подтверждении, что POST ещё не начинался; после отправки и при неизвестном состоянии повторы запрещены. Полностью пустой анализ не кешируется, старый пустой кеш игнорируется и неполнота явно сообщается. Существующие 13 ответов `Reading` не удалены и могут использоваться повторно при совпадении запроса.

Прошли **88 тестов**, включая ограниченные повторы подключения до POST, отсутствие повторов после начала POST, обход старого пустого кеша, сохранение принятой правки после сбоя следующего уточнения, возврат валидного проекта и отдельную обработку отмены. Компиляция и `pip check` прошли. Новые платные обращения к провайдеру не выполнялись; сетевой сбой как внешнее событие не объявляется устранённым, а качество группировки после нового запроса остаётся непроверенным.
