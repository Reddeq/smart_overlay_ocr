# Smart Overlay OCR

**Чертёж → редактируемый PowerPoint.** Настольное приложение для подготовки технических схем и рисунков к переводу.

Выберите PNG/JPG/TIFF/BMP, при необходимости укажите языковую пару и нажмите **«Распознать → PPTX»** — программа создаст презентацию **рядом с исходным файлом**. Уже существующий PPTX не перезаписывается; следующему результату добавляется суффикс `-01`, `-02` и т. д.

- Исходное изображение остаётся **целиком и без изменения пикселей** нижним слоем; размер слайда пропорционален источнику.
- Надписи становятся редактируемыми PowerPoint-фреймами с заливкой, закрывающей старый текст. Многострочные подписи группируются в один фрейм, когда это подтверждает алгоритм.
- Линованные таблицы превращаются в нативные редактируемые таблицы PowerPoint с ячейками и объединениями.
- Чистые числовые обозначения и очевидные самостоятельные коды **остаются на исходном изображении**; код внутри переводимой фразы сохраняется вместе с текстом.
- Форматирование старается сохранить исходные размеры, ориентацию и цвет фона; неоднозначные места остаются отмеченными для проверки.
- При ошибке необязательной облачной проверки программа создаёт результат локального OCR и сообщает об ограничениях — исходный файл не повреждается.

## Запуск на Windows

Требуются Python 3.11/3.12 x64, Node.js 22/24 и Microsoft Visual C++ Redistributable 2015–2022 x64. При первом запуске PaddleOCR скачивает веса моделей; затем локальное OCR работает без сети.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
npx --yes pnpm@11.25.0 install --frozen-lockfile
.\.venv\Scripts\python.exe -m smart_overlay
```

Либо запустите `run.ps1`. Откроется **новое простое окно** с выбором чертежа, кнопкой распознавания и предпросмотром.

**Для исправлений:** после обработки нажмите «Исправить результат…» — откроется подробный редактор объектов и таблиц. Он больше не является главным окном.

## Языки OCR

В главном окне есть кнопка **«Языки OCR: Автоопределение»**. По умолчанию распознавание пробует определить наиболее вероятные письменности, включая китайскую/японскую, латинскую, кириллицу, корейскую и арабскую. Автоопределение эвристическое и не гарантирует распознавания всех языков; на сложных схемах лучше выбрать известные языки вручную.

Нажмите кнопку для выбора нескольких языков или готовой пары: **русский + английский**, **китайский + английский**, **японский + английский**, **китайский + русский**. Также доступны корейский, арабский и основные европейские языки с латиницей. Список сохраняется между запусками. **Переключение влияет на локальный OCR:** программа подбирает соответствующие распознаватели PaddleOCR, а не только меняет подсказку для VL.

Для PP-OCRv5 некоторые языки обслуживаются одной общей моделью: например, `ch,en` — один китайско-английский распознаватель, `ru,en` — восточнославянская модель с английским. Для сочетания разных письменностей (например, `ch,ru`) текстовые строки повторно читаются второй специализированной моделью, но **геометрия детектируется один раз**. Неоднозначные результаты помечаются для проверки; выбор между разными моделями основан на ограниченной эвристике письменности и уверенности, а не на обученном отдельном классификаторе. При первом использовании новые модели могут скачиваться, а автоматический режим может быть медленнее ручного.

Для CLI используйте `convert drawing.png` (авто) или `convert drawing.png --languages ch,ru` (ручной набор). Прежний режим `recognize` с отдельным параметром `language` оставлен для совместимости.

## Локальный нейросетевой OCR (эксперимент)

Если обычный PaddleOCR не справляется с текстом, переключите **«Способ распознавания → PaddleOCR-VL 1.6 · локально»**. Он читает чертёж самостоятельно, без входных фрагментов стандартного OCR и без OpenRouter. При первом запуске потребуются скачанные веса модели; в процессе распознавания чертёж остаётся на компьютере. По умолчанию используется **CPU**, поскольку на видеокартах с 6 ГБ VRAM модель может не поместиться. GPU можно выбрать отдельно.

Из-за ограничений геометрии PaddleOCR-VL **все полученные текстовые фреймы и таблицы требуют визуальной проверки**. Результат и диагностика сохраняются локально: структурный ответ, сводка спорных областей и изображение с рамками. Это отдельный режим, обычный Smart OCR не изменяется.

Для установки версии PaddleOCR, совместимой с VL-1.6, используйте **отдельное окружение**: [установка и тестирование PaddleOCR-VL на Windows](docs/local-vl.md).

CLI:

~~~powershell
.\.venv-vl\Scripts\python.exe -m smart_overlay convert "drawing.png" --ocr-engine vl_local --vl-device cpu --vl-diagnostics ".\\outputs\\paddle-vl"
~~~

## Улучшенное Smart OCR (необязательно)

Без настроек программа сразу работает локально (PaddleOCR, OpenCV, восстановление сеток, PPTX). Для более качественной **смысловой группировки**:

1. В «Настройках» укажите язык (`ru` или `en`), API-ключ OpenRouter и адрес **уже работающего** HTTP-прокси Xray (типовой пример `http://127.0.0.1:10809`).
2. Включите облачную проверку. Для **каждого** исходного файла перед передачей данных приложение запрашивает отдельное согласие; при отказе продолжает локально.
3. Нажмите «Распознать → PPTX». Проверка VPN выполняется до платных запросов. Используется `qwen/qwen3-vl-8b-instruct` через Parasail, **оконная дифференциальная группировка** с улучшенным промптом, проверкой геометрии и согласованием перекрытий, а не старый глобальный `Analysis`.
4. Для обнаруженных таблиц с отметкой проверки дополнительно запрашивается VL-проверка сетки (без массовых отдельных запросов на чтение каждого символа). Все предложения проходят структурную проверку; неподтверждённые места требуют ручной проверки.

По умолчанию максимальное число обращений одного процесса — **24** (группировка + проверка таблиц), без автоматических повторов после отправки POST. Число фактических запросов зависит от чертежа. Облачная обработка оплачивается по тарифам API; общего денежного потолка в приложении нет. Ключ хранится только в памяти процесса или берётся из `OPENROUTER_API_KEY`, на диск не записывается. VPN приложение не запускает и глобальные сетевые настройки не меняет.

Промежуточные редактируемые проекты (`.socr.json`) автоматически сохраняются в `%LOCALAPPDATA%\SmartOverlayOCR\projects`. Они содержат оригинал и OCR-текст, поэтому храните их как рабочие документы.

## CLI

```powershell
# Локальный чертёж -> PPTX
.\.venv\Scripts\python.exe -m smart_overlay convert "drawing.png"

# Через уже работающий VPN и OpenRouter (требует OPENROUTER_API_KEY)
.\.venv\Scripts\python.exe -m smart_overlay convert "drawing.png" --smart --consent-api --proxy "http://127.0.0.1:10809"

# Отдельный подробный редактор при необходимости
.\.venv\Scripts\python.exe -m smart_overlay editor
```

Старые команды `recognize`, `export`, `replay-vl` и диагностические скрипты сохранены для совместимости и анализа.

## Известные ограничения

- **PDF и многостраничный TIFF пока не поддерживаются**: сначала экспортируйте нужную страницу в изображение. Один входной файл = один слайд.
- Точность исходного OCR и восстановления сложных/повёрнутых таблиц не гарантирована. Перед отправкой в CAT/перевод стоит визуально проверить PPTX, особенно элементы с отметкой проверки.
- Порог и качество VL-подсказок ещё не подтверждены на большой независимой подборке схем; одиночные предложения и конфликты помечаются как неопределённые.
- Внешний вид текстовых рамок и их переносы могут отличаться от PowerPoint; источник всегда сохраняется на фоне.
- Без доступного API и согласия на передачу документа работает только локальный OCR.

Подробные исследования и технические ограничения: [локальный поиск таблиц](docs/automatic-tables.md), [оконная VL-группировка](docs/grouping-editor.md), [проверка табличных сеток](docs/table-review.md), [проверка на полном листе](docs/vl-full-sheet-experiment.md).

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q smart_overlay
```

Нет необходимости устанавливать Microsoft PowerPoint для создания PPTX; он пригодится для визуальной проверки.
