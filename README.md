# Smart Overlay OCR — MVP 0.1

Windows-приложение для создания редактируемых текстов и настоящих таблиц PowerPoint поверх исходной схемы. Автоматического перевода нет. Интерфейс — PySide6; локальное распознавание — PaddleOCR / TableRecognitionPipelineV2 и OpenCV; Smart OCR — мультимодальный OpenAI-совместимый Chat Completions API; экспорт — PptxGenJS.

## Установка на Windows 10/11 x64

Нужны Python **3.11 или 3.12 x64**, Node.js **22 LTS или 24** с npm, CPU с AVX и Microsoft Visual C++ Redistributable 2015–2022 x64. Используется CPU-версия PaddlePaddle. PowerPoint для генерации файла не требуется.

В PowerShell из каталога проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
npx --yes pnpm@11.25.0 install --frozen-lockfile
.\.venv\Scripts\python.exe -m pip check
```

`requirements.txt` фиксирует прямые зависимости. `requirements-lock.txt` фиксирует также транзитивные зависимости проверенного окружения Windows / Python 3.12.14; включает pytest. `pnpm-lock.yaml` фиксирует зависимости генератора. Библиотеки и модели не включены в Git. Первый запуск OCR скачивает официальные веса PaddleOCR (суммарно несколько крупных моделей); последующие используют локальный кеш. При проблемах загрузки используйте рабочее подключение/VPN. После предварительной загрузки моделей OCR Only не требует сети и не отправляет изображения в API.

Официальные интерфейсы проверены по исходникам [PaddleOCR 3.3.2](https://github.com/PaddlePaddle/PaddleOCR/tree/v3.3.2/paddleocr/_pipelines), установленному PaddleX 3.3.13 и [PptxGenJS 4.0.1](https://github.com/gitbrent/PptxGenJS/tree/v4.0.1). Поддержка `rowspan` / `colspan`, размеров строк, заливок и границ дополнительно проверяется по XML созданной презентации. Это консервативно зафиксированная связка, а не автоматическая установка последних версий.

Для таблиц выбран разрешённый ТЗ специализированный **TableRecognitionPipelineV2** — тот же табличный конвейер, который использует PP-StructureV3. Причина выбора по результатам запуска: PaddleX 3.3.13 инициализирует ChartRecognition в PP-StructureV3 даже при отключённом распознавании графиков. Специализированный вариант исключает эту ненужную модель и использует результаты первичного OCR. Автоповорот таблиц отключён; повёрнутые таблицы требуют ручной проверки. Дополнительный поиск сеток OpenCV восстанавливает таблицы, которые модель разметки страницы пропускает внутри рисунка; такие результаты всегда помечаются для проверки.

## Запуск и работа

```powershell
.\.venv\Scripts\python.exe -m smart_overlay
# либо
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

`run.ps1` использует кеш моделей `.cache\paddlex` внутри проекта; в подготовленном рабочем каталоге веса уже загружены. При прямом запуске Python можно задать `PADDLE_PDX_CACHE_HOME` явно либо использовать стандартный кеш PaddleX.

Для экспорта Node.js ищется в `PATH`, затем в `.runtime/node/node.exe` внутри проекта и стандартных каталогах установки Windows. В этом рабочем каталоге локальный runtime уже подготовлен; экспорт работает и при запуске GUI без Node.js в `PATH`. Для собственного расположения задайте переменную `SMART_OVERLAY_NODE` с полным путём к `node.exe`. Каталог `.runtime`, как и `.venv`/`node_modules`, исключён из Git; при переносе исходников на другой компьютер установите зависимости заново или подготовьте локальный runtime. Глобальные настройки `PATH` приложение не меняет.

1. Откройте PNG, JPEG, TIFF или BMP. Для знакомства можно открыть `examples/technical-demo.socr.json`.
2. В настройках выберите язык (`en`, `ru` и т. п.) и профиль OCR. Совместимость языка с профилем проверяет PaddleOCR; для новых языков предпочтителен PP-OCRv5.
3. Выберите **Smart OCR** или **OCR Only**, нажмите «Распознать». Тяжёлые операции выполняются в рабочем потоке. Локальное OCR завершается до запроса согласия на API. Во время Smart OCR статус показывает подготовку изображений, размер запроса, попытку, подключение DNS/TCP/TLS, отправку, HTTP-код и время ожидания. Кнопка «Отменить Smart OCR» прерывает сетевое ожидание и оставляет локальные результаты доступными.
4. Зелёные области — логические текстовые блоки, синие — таблицы, жёлтые требуют проверки. Колесо мыши меняет масштаб, перетаскивание перемещает вид. Выберите объект в списке или на изображении; Ctrl позволяет выбрать несколько.
5. Измените текст, координаты/размеры в пикселях, поворот, заливку, шрифт и выравнивание; нажмите «Применить свойства». Для таблицы свойства оформления применяются ко всем ячейкам. «Добавить текст» позволяет нарисовать новую область. Блоки можно объединить, разделить с явной геометрической границей, преобразовать в таблицу/текст, повторно распознать или исключить из экспорта.
6. «Редактировать таблицу» открывает сетку с редактируемым содержимым. Прямоугольное выделение объединяется, выбранная объединённая ячейка разделяется. Можно изменить число строк/столбцов, ширины и высоты, заливку и границы выбранных ячеек. При перестроении сетки тексты сохраняются в первой ячейке для распределения вручную. Суммы ширин и высот должны совпадать с размерами области.
7. При необходимости проверьте сомнительные области и отметьте «Объект проверен». При экспорте непроверенных объектов приложение показывает предупреждение: можно продолжить или отменить экспорт. Отметки проверки сохраняются. Ненужные объекты можно явно исключить. Проверки целостности проекта (координаты, OCR ID, структура ячеек) остаются обязательными.
8. Сохраните переносимый проект `.socr.json`, затем экспортируйте PPTX. Повторное открытие и экспорт не запускают OCR или API. Изменения свойств применяются кнопкой; переход к другому объекту не применяет незавершённые правки формы.

Настройки хранятся в `%LOCALAPPDATA%\SmartOverlayOCR\settings.json`. Ключ хранится только в памяти процесса либо читается из `OPENROUTER_API_KEY`, в настройки и проект не записывается. Кеш ответов находится в `%LOCALAPPDATA%\SmartOverlayOCR\cache`; он содержит распознанный текст и может быть удалён пользователем. Проект также содержит исходное изображение и OCR-текст; учитывайте это при передаче файла.

Отклонённые ответы и сведения о незавершённом HTTP-ответе записываются в `%LOCALAPPDATA%\SmartOverlayOCR\diagnostics\vl-failure-N.json`; путь показывается в уведомлении об ошибке. Диагностика содержит ответ модели, текст и координаты OCR для локального воспроизведения проверки. Изображения, входящий запрос и API-ключ не сохраняются; приватные поля ответа очищаются. Используются фиксированные слоты по числу попыток (максимум шесть), каждый файл ограничен 4 МБ. Если контекст не помещается, это отмечается явно.

## Подключение OpenRouter

В «Настройки» задайте endpoint `https://openrouter.ai/api/v1`, ID выбранной **мультимодальной модели с поддержкой JSON-ответов** и API-ключ. Модель намеренно не зафиксирована в коде. Endpoint указывается без `/chat/completions`. Можно использовать другой HTTPS endpoint с совместимым интерфейсом. Ключ не передаётся через аргументы командной строки.

Используется `response_format: {"type": "json_object"}` с JSON Schema в системном сообщении, локальная проверка Pydantic и геометрическая валидация. Сведения о [формате структурированных ответов](https://openrouter.ai/docs/guides/features/structured-outputs) и [передаче изображений](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding) — в документации провайдера. Поддержка зависит от модели и её endpoint; неподдерживаемый формат приводит к явной ошибке и сохранению локальных результатов.

При отказе проверки журнал и уведомление показывают этап и причину: формат ответа API, конкретное поле схемы JSON или ошибка геометрии/связей OCR. Повторный запрос передаёт предыдущий ответ и конкретные замечания для исправления полного документа. Допускается один внешний блок Markdown ` ```json ` вокруг полного JSON; произвольные фрагменты из текста не извлекаются. API-ключ и значения невалидных полей в диагностику схемы не записываются. Ошибка записи кеша не приводит к повторному платному запросу, если ответ уже успешно проверен.

Если модель не вернула проверку одной или нескольких таблиц, Smart OCR сохраняет их локальную сетку и содержимое, помечает для ручной проверки и применяет корректную группировку остального текста. Если модель вернула табличный текст обычными блоками, он остаётся в ячейках, а таблица получает предупреждение; дублирующие фреймы не создаются. Неизвестные/повторяющиеся ID таблиц, объединение табличного и обычного текста и другие нарушения целостности по-прежнему отклоняются.

Если модель пропустила обычные OCR-фрагменты в своём ответе, корректные группы всё равно применяются. Полностью пропущенные локальные блоки сохраняются с текстом, ручными исправлениями и положением; пропущенная часть частично обработанного блока восстанавливается по исходной геометрии OCR без произвольного деления текста. Такие объекты помечаются для проверки, в журнале указывается число пропущенных фрагментов. Одна лишь неполнота ответа не запускает три одинаковых запроса. Фрагменты, явно исключённые с причиной, не восстанавливаются, табличный текст не дублируется. Итоговый проект по-прежнему обязан учитывать каждый OCR ID ровно один раз.

Полностью пустой структурный ответ явно обозначается как неполный и не записывается в кеш. Старые пустые записи кеша пропускаются; запрос дополнен примером группы для реального OCR ID. Пустой ответ не подтверждает качество группировки: локальные блоки остаются с отметками проверки, даже если отдельные уточнения текста были успешны.

Уточнение сомнительных фрагментов показывает текущий номер и общее количество. Если одно из дополнительных уточнений завершилось ошибкой, ранее полученные правки сохраняются, новые платные уточнения в этом проходе прекращаются, оставшиеся фрагменты отмечаются для проверки. Приложение возвращает доступный проект вместо отказа всего Smart OCR. В журнале указываются число полученных/принятых уточнений и причина остановки. Пользовательская отмена обрабатывается отдельно.

**Перед отправкой каждого запуска Smart OCR приложение запрашивает согласие**, показывая endpoint и модель. Передаются изображение, пронумерованная разметка, координаты, OCR и структура таблиц; для крупных изображений добавляются фрагменты с контекстом. При низкой уверенности выполняются отдельные запросы с увеличенными фрагментами. Запросы могут тарифицироваться. Кеш учитывает изображение, модель, endpoint, схему и параметры запроса. Учитываются токены и стоимость, если API их возвращает; попадания в кеш отмечаются отдельно. Ошибки авторизации не повторяются; сетевые ошибки и невалидные ответы имеют ограниченное число повторов. Перенаправления API запрещены, чтобы не пересылать ключ другому хосту.

В настройках заданы отдельные тайм-ауты: подключение — **10 секунд**, полный срок одной сетевой попытки — **120 секунд** по умолчанию. Полный срок охватывает отправку и получение тела ответа и не продлевается при поступлении служебных байтов. После начала отправки POST локальный тайм-аут не вызывает автоматический повтор: сервер мог уже принять запрос. Если трассировка явно подтверждает, что отправка POST ещё не началась и HTTP-ответ отсутствует (например, тайм-аут TLS), разрешены ограниченные повторы подключения согласно настройке повторов. При недостаточных данных об отправке повтор не выполняется. Отмена также не вызывает повторный запрос и не снимает отметки ручной проверки. При повторном OCR выделенных областей отмена проверяется между вызовами Paddle; принудительного завершения инференса нет. Прекращение локального ожидания не гарантирует, что провайдер остановит уже принятую генерацию или не начислит стоимость.

По умолчанию включён потоковый ответ VL. Приложение обрабатывает [SSE-поток Chat Completions](https://openrouter.ai/docs/api_reference/streaming): служебные комментарии не считаются текстом модели, статус показывает число полученных символов, токены учитываются из завершающего события. Поддерживаются и обычные JSON-ответы. Для несовместимого endpoint потоковый режим можно отключить в настройках. Лимит выходного ответа — 8192 токена, настраивается; при `finish_reason=length` одинаковый запрос не повторяется автоматически. JSON при этом не принимается за полный результат.

Обмен с моделью сокращён: неизменённые надписи возвращаются как `ocr_ids` и `confidence` без повторения текста, неизменённые таблицы — с размерами и уверенностью без полной копии ячеек. Стили PowerPoint и внутренние ID ячеек в задание модели не передаются. Внутренний формат проекта и проверки геометрии сохраняются. Потоковый режим позволяет отличить активную генерацию от служебных сигналов, но не гарантирует скорость внешнего провайдера; общий лимит ожидания продолжает действовать.

HTTP `200` сам по себе не означает успешную генерацию: клиент также проверяет `error` в теле ответа, как описано в [документации OpenRouter](https://openrouter.ai/docs/api_reference/errors-and-debugging#non-streaming-requests). Отметка «запрос отправлен» подтверждает завершение передачи тела со стороны клиента; HTTP-код подтверждает ответ API. Подключение к HTTPS-прокси не выдаётся за отправку запроса модели. В журнал не записываются ключ, содержимое изображений или внутренние метаданные HTTP-трассировки.

Если API недоступен, приложение оставляет локальный результат и предлагает продолжить в OCR Only. Кнопка «VL для текущего OCR» повторяет анализ без первичного OCR. Никаких запросов на реальный OpenRouter при разработке/автотестах без ключа пользователя не выполняется.

## Командная строка

Для изолированного исследования пустых VL-ответов доступна команда `diagnose-vl`. Без `--execute` она только строит план, без сети. Тесты A–F, визуальная проверка и дифференциальный прототип, ограничения запросов, команды запуска и фактические выводы описаны в [отчёте диагностики](docs/vl-diagnosis.md). Основной Smart OCR этот эксперимент не использует.

```powershell
# Полностью локальное OCR, промежуточные результаты и исходник в JSON
.\.venv\Scripts\python.exe -m smart_overlay recognize examples\technical-demo.png --project outputs\local.socr.json

# Smart: заполните model в собственной копии settings.example.json;
# OPENROUTER_API_KEY должен быть установлен в окружении.
.\.venv\Scripts\python.exe -m smart_overlay recognize input.png --project outputs\smart.socr.json --mode smart --settings settings.local.json --consent-api

# Экспорт уже проверенного проекта без OCR/API
.\.venv\Scripts\python.exe -m smart_overlay export examples\technical-demo.socr.json outputs\demo.pptx

# Экспорт непроверенных объектов с предупреждением в консоли
.\.venv\Scripts\python.exe -m smart_overlay export outputs\local.socr.json outputs\draft.pptx --allow-unreviewed

# Повторная проверка сохранённого ответа локально, без OCR и платного API
.\.venv\Scripts\python.exe -m smart_overlay replay-vl "C:\path\to\vl-failure-1.json"
```

Smart CLI сначала сохраняет локальный проект. При отказе API сохраняет доступный результат и возвращает код 2. В GUI экспорт непроверенных объектов разрешён после предупреждения; в CLI используйте `--allow-unreviewed`. Флаг обходит только отметки ручной проверки, сохраняя геометрическую и структурную валидацию. Настройки `inches_per_pixel` определяют физический размер слайда: `width_px × коэффициент`, `height_px × коэффициент`. Для получения исходных пиксельных размеров экспортируйте растр с DPI, равным `1 / коэффициент` (по умолчанию 150). Допустимый размер слайда в приложении: 1–56 дюймов по каждой стороне; при выходе за пределы требуется изменить коэффициент.

`replay-vl` применяет текущие правила разбора и геометрии к сохранённому полному ответу: код 0 означает успешную проверку, 2 — воспроизведённую ошибку. Незавершённый HTTP-ответ не содержит окончательного JSON модели; в таком случае диагностический файл служит для анализа этапа, объёма полученных данных и ID генерации, а не для восстановления отсутствующего ответа.

## Формат проекта и модули

Единый JSON имеет `version: 1`. `source` содержит имя без локального пути, размеры, режим, EXIF-ориентацию, SHA-256 и оригинальные байты в Base64. `raster_b64` — отображаемая копия; PNG/JPEG без EXIF-преобразований RGB/L встраиваются без перекодирования. TIFF, BMP, палитровые изображения и изображения с EXIF-ориентацией представлены в PPTX как PNG отображаемого растра; оригинальные байты остаются в проекте. Исходные пиксели не ретушируются и не очищаются от текста.

Координаты — пиксели отображаемого изображения после EXIF-ориентации, начало сверху слева, `bbox: {x,y,w,h}`, многоугольники — пары `[x,y]`, поворот — градусы по часовой стрелке. OCR-фрагменты имеют стабильный ID, текст, полигон, угол, уверенность и источник. Объекты ссылаются на `ocr_ids`; таблицы содержат нумерацию строк/столбцов с нуля, устойчивые ID ячеек, spans, размеры сетки, стиль и принадлежность OCR. Исправления текста и причины исключения сохраняются. Ручное разделение создаёт геометрически заданные дочерние фрагменты со ссылкой на родителя. Сырые ответы PaddleOCR / табличного конвейера и предложения OpenCV хранятся в `raw`; исходные фрагменты не теряются при последующем повторном OCR.

Модули в `smart_overlay/`: `input.py`, `ocr.py`, `tables.py`, `vision.py`, `vision_transport.py`, `structure.py`, `geometry.py`, `formatting.py`, `pipeline.py`, `models.py`, `settings.py`, `app.py`, `export/`. HTTP-транспорт использует httpx с ограничением времени и кооперативной отменой внутри фонового потока. Генератор принимает промежуточный документ, не зависит от OCR и не обращается к API. Текст и его непрозрачная заливка принадлежат одному PowerPoint-объекту; отдельные подложки не создаются. Таблицы — нативные `a:tbl`, включая `gridSpan`, `rowSpan`, `hMerge`, `vMerge`.

## Проверки и примеры

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q smart_overlay
.\.venv\Scripts\python.exe examples\create_example.py
```

`examples/technical-demo.png` — синтетическая схема. `technical-demo.socr.json` — **вручную заданная эталонная разметка**, а не выдача OCR/VL. `technical-demo.pptx` — экспорт этой разметки с тремя текстовыми объектами и таблицей 4×3 с горизонтальным и вертикальным объединением. Этот пример доказывает возможности экспорта, но не точность распознавания.

Проверка на этой машине: реальный PaddleOCR обнаружил 16 текстовых фрагментов; модель layout пропустила таблицу внутри рисунка, а дополнительный OpenCV нашёл сетку 4×3 с правильными объединениями и текстами девяти ячеек. Повторный запуск с загруженными моделями занял около 20 секунд. OCR Only также успешно выполнен при ограниченном сетевом доступе с использованием кеша. Это один синтетический пример, не измерение качества на реальных документах. Итоги и оставшаяся проверка приведены в `docs/verification.md`.

Автотесты проверяют сохранность исходника, повторное открытие, EXIF и форматы, валидацию владения OCR, потерянные/повторяющиеся ID, границы таблиц, ручное объединение/разделение, схему VL, пороги исправлений, согласие, кеш, повторы, отказ API, локальный режим, запуск GUI и нативную структуру PPTX. Сетевой клиент в unit-тестах подменяется контролируемыми ответами; генератор PPTX и Qt используются настоящие.

## Ограничения и состояние проверки

- Живой Smart OCR требует ключа, выбранной модели и согласия пользователя. Без этого проверены только клиент, схемы и правила обработки на контролируемых ответах; качество реальной VL-модели не измерено.
- Нет набора из 5–10 реальных схем пользователя. Не заявляется процент точности или прохождение приёмки на таких данных. Для оценки фиксируйте найденные подписи, неверные объединения/разделения, ошибки ячеек, исправления, число ручных правок, время и стоимость из журнала.
- Сложные, повёрнутые, безлинейные и нерегулярные таблицы могут требовать ручной разметки. Объединения и расхождения OpenCV/HTML явно помечаются. Неопределённая структура сохраняется как область с отметкой проверки; рекомендуется задать сетку вручную. Экспорт такой области разрешён после предупреждения и может содержать неточную структуру. Текст таблицы не дублируется отдельными фреймами.
- Автофон — доминирующий цвет с исключением контуров и тёмных пикселей, приблизительный для неоднородного фона. Оценка шрифта/переполнения приблизительная; шрифтовые метрики и переносы могут отличаться в PowerPoint.
- Проверка PowerPoint XML не заменяет ручное открытие файла в установленном Microsoft PowerPoint. Необходимо проверить редактирование, отсутствие обрезания и внешний вид на реальных схемах.
- Один файл — один слайд, многостраничный TIFF отклоняется. OCR геометрической постобработки сохраняет самостоятельные строки консервативно; смысловая группировка выполняется в Smart OCR.
- Повторный анализ новых геометрических областей ограничен одним дополнительным проходом VL; неуверенные или повторно запрошенные области требуют проверки. Для крупных изображений действует предел 64 детальных фрагмента в одном запросе; лимиты изображений конкретного провайдера могут быть ниже.
- Сетевую/модельную ошибку распознавания таблиц приложение сообщает явно. Перед закрытием приложения дождитесь текущей фоновой операции либо отмените Smart OCR; принудительного прерывания Paddle-инференса нет.

Автоматический перевод, PDF, inpainting, векторизация и обучение моделей в MVP не входят.
